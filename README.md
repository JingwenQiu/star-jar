# Superstar's Star Jar

一个给小朋友用的星星罐奖励工作台。**纯前端、无需注册、离线可用**，数据保存在本机，
可选接入 Supabase 云端在多设备间同步。

线上地址：<https://jingwenqiu.github.io/star-jar/>

---

## 设计前提（来自原始表格的第二页）

这些不是功能，是**不可违反的规则**，写死在代码里：

| 规则 | 说明 |
|---|---|
| **星星永不减少** | 兑换奖品只扣「可支配余额」，罐子里的总数和填充百分比永远不下降 |
| **没打卡就是 0，不是负数** | 漏掉一天不会倒扣 |
| **心情不打分** | 😊🙂😐😕😢 只用于观察规律，不参与任何计算 |
| **正反馈为主** | 全部文案避免评价性语言 |

> 依据：原表格写明，对一个已经觉得自己「什么都不擅长」的孩子，扣星星只会印证她的想法。
> 因此消费只影响可支配余额，已赚到的星星永远计入填充进度。

### 数据

| 层 | 说明 |
|---|---|
| **localStorage** | 同步写入，即时生效 |
| **IndexedDB** | 真正落盘的数据库层，写入做 400ms 防抖 |
| **冲突处理** | 启动时比较两边 `savedAt`，**新的胜出**——清掉任一层都不丢数据 |
| **事件日志** | **只追加、按 ID 唯一**，用 `add()` 而非 `put()`，**覆盖在结构上不可能发生** |
| **导入导出** | JSON（整罐）/ JSONL（一行一条事件）/ CSV（含正确转义） |
| **合并导入** | 星星取**并集**，绝不覆盖；导入前显示差异预览 |

## 星星是怎么算的

```
某天星数 = 任务星数之和 + 手动额外奖励

累计总数 = 各天星数之和 + 之前周结余
可支配   = 累计总数 − 已兑换奖品花费
填充进度 = 累计总数 / 目标星数        ← 兑换不会让它下降
```

- **星星只来自勾选任务**。勾一个 1★ 任务就是 1★，勾一个 3★ 就是 3★
- **打卡本身不额外加星**（原表的「打卡 +1」已移除）
- **一周全勤也没有额外奖励**（原表的「彩虹 +5」已移除）
- 额外奖励只能用「Bonus stars」手动添加

> 换句话说：任务上写几颗，就是得几颗。打卡奖励和彩虹奖励这两条已按你的要求移除。

## 云同步（可选）

不登录也完全能用。登录后每台设备登录一次，之后自动同步。

1. supabase.com 建免费项目
2. SQL Editor 运行 `SUPABASE-SETUP.txt`
3. **Authentication → URL Configuration**：把 **Site URL** 和 **Redirect URLs** 都设成本站地址
   （新项目 Site URL 默认是 `http://localhost:3000`，不改会导致登录链接 404）
4. Project Settings → API 复制 **API URL** 和 **publishable key**
5. 页面底部 **Cloud account** → 粘贴 → **Connect**
6. 右栏 **Keep in sync** → 填邮箱 → **链接**或 **6 位验证码**登录

> **验证码更稳**：部分邮箱（尤其 QQ 邮箱）会重写链接并丢掉令牌，导致点链接没反应。
> 遇到这种情况点「**Enter the 6-digit code**」，验证码不会被改写。

同步原理：事件日志只追加、按 ID 唯一，数据库有 `UNIQUE (owner_id, event_id)` 约束，
两台设备同时上传同一条事件只会保留一份。**先拉取再上传，合并时星星取并集**，永不互相覆盖。
`jar_events` 表**没有** UPDATE / DELETE 权限——只追加由数据库强制。

## 首次使用

1. **右上角齿轮** → 填名字、装满要多少星（默认 60）、奖励是什么、以前攒了多少星

## 文件结构

```
index.html      页面结构
styles.css      设计系统（马卡龙色板、组件、响应式）
data.js         数据模型 + 全部计算 + 存储层（localStorage / IndexedDB / 事件日志）
cloud.js        内置云同步（备用，当前凭据被拒，不自动展示）
supabase.js     Supabase 同步（邮箱登录 + 快照/事件上传）
app.js          渲染与交互
sw.js           Service Worker（离线缓存）
manifest.json   PWA 清单
vendor/         第三方库（Supabase 客户端、云 SDK），从本站加载而非 CDN
SUPABASE-SETUP.txt   建表 SQL（.sql 被静态托管屏蔽，故用 .txt）
SUPABASE-GUIDE.md    接入步骤与排错
verify.mjs      测试套件
```

## 开发

```bash
node verify.mjs          # 394 项断言
node --check app.js      # 语法检查（五个 JS 文件都应通过）
```

改了任何文件后**务必**：

1. 跑 `verify.mjs`
2. **升 `sw.js` 里的 `CACHE` 版本号**——否则已装到桌面的旧版本会继续用缓存
